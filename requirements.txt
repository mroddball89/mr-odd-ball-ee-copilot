# Mr Odd Ball — EE Copilot
# LOWER BOUNDS, NOT PINS — the same convention the assistant half already used.
#
# These were `~=` pins copied from a Windows environment where the packages were already
# installed in a mutually compatible set. On a FRESH aarch64 venv that set is unreachable:
# pinning langchain-core to ~=1.5 while langchain-community and langchain-google-genai each
# constrain it from opposite directions gave pip a ResolutionImpossible, and its error named
# langchain-core, which resolves fine on its own. An hour of the Pi bring-up went into that.
#
# A pin that only works on the machine it was captured on is not a pin, it is a snapshot. Let
# pip solve it, and pin exactly only if the two boxes ever actually disagree.

# =======================================================================================
# The assistant half — wake word, ears, voice, face. Merged from mroddball89/mr-odd-ball-ai.
#
# Lower bounds rather than pins, matching that repo: built against Python 3.12.10 on Windows
# and 3.13.5 on the Pi.
#
# TWO THINGS THAT ARE NOT IN THIS FILE and are not optional on the Pi:
#
#   sudo apt install libportaudio2 pipewire-alsa
#   pip install --no-deps "openwakeword>=0.6.0"
#
# `pipewire-alsa` is the one that is easy to miss: PortAudio speaks ALSA, and without that
# plugin ALSA has no route to the PipeWire sink the Bluetooth speaker lives on — playback
# "succeeds" into the HDMI card while the speaker sits silent.
#
# `--no-deps` because openWakeWord declares tflite-runtime as a hard dependency on Linux, and
# tflite-runtime publishes no wheels for Python 3.12+, so pip refuses to install it at all on
# the Pi. We never load tflite — config/oddball.toml sets framework = "onnx" on both boxes.
# Its real dependencies are listed at the bottom, which is what makes the flag safe.
# =======================================================================================

sounddevice>=0.5.5                   # PortAudio bindings — the microphone AND the speaker
numpy>=2.5.2
websockets>=17.0.1                   # the face link; websockets.asyncio, not the legacy API
piper-tts>=1.6.0                     # his voice. Reuses onnxruntime, so ~34MB not a 2nd runtime
faster-whisper>=1.2.1                # his ears. ctranslate2 ships a cp313 aarch64 wheel

# --- openWakeWord's real dependencies, because it is installed with --no-deps ------------
onnxruntime>=1.10,<2
tqdm>=4.0,<5.0
scipy>=1.3,<2
scikit-learn>=1,<2
requests>=2.0,<3

# =======================================================================================
# The desktop avatar and gesture approval. Added 2026-08-21.
#
# ALL FOUR ARE OPTIONAL AT RUNTIME and every import of them is guarded, which is deliberate
# and is the reason they are last in this file:
#
#   no fastapi/uvicorn -> `--avatar` logs a warning and the assistant runs without a ball
#   no opencv/mediapipe -> get_gesture() returns NO_CAMERA and approval falls to the keyboard
#
# A missing UI extra must never cost the voice loop. The stdlib-only `ui/avatar_state.py`
# exists precisely so `orchestrator/hud_bridge.py` can mirror state into the overlay without
# importing FastAPI on the critical path.
# =======================================================================================

fastapi>=0.115                       # serves ui/avatar.html at /ui, and the /ws/state socket
uvicorn>=0.34                        # the ASGI server; ui/server.py runs it in a daemon thread

# NOT Chromium. A Chromium window for a 120px ball is ~250MB and a core of a Pi 5 that is
# already running whisper, piper and onnxruntime. pywebview wraps the system WebKit view,
# which the desktop already has resident.
#
# TWO THINGS THAT ARE NOT IN THIS FILE, in the same class as libportaudio2 above — pip installs
# pywebview happily and `webview.start()` then fails looking for a GUI toolkit:
#
#   sudo apt install python3-gi gir1.2-webkit2-4.1 python3-gi-cairo
#
# `transparent=True` also needs a compositing WM. Bookworm's Wayfire session composites; a
# bare X11 session with no compositor gives an opaque window instead. Cosmetic, not broken.
pywebview>=5.3

# Gesture approval — a thumbs up at the camera instead of typing y (tools/gesture_control.py).
#
# >= 1.0, AND THE LOWER BOUND IS THE WHOLE POINT. Corrected 2026-08-22; see D14.
#
# The first version of this line said `mediapipe>=0.10.14` on the reasoning that aarch64 wheels
# stop at cp312 and the Pi is on 3.13.5. Both halves of that were checked against the 0.10.x
# series only, and the series moved:
#
#   0.10.18   last release with an aarch64 wheel at all       cp39-cp312   has mp.solutions
#   0.10.20+  NO aarch64 wheels whatsoever                                 has mp.solutions
#   1.0.1     mediapipe-1.0.1-py3-none-manylinux_2_28_aarch64  ANY py3     mp.solutions REMOVED
#
# `py3-none` is ABI-independent, so 1.0.1 installs on the Pi's existing 3.13.5 venv — verified
# with `pip install --dry-run` on the box itself, which resolves it cleanly. No Python
# downgrade is needed and none should be done for this.
#
# The floor is >=1.0 rather than unpinned because a resolver free to pick 0.10.x on a 3.12 box
# would silently select the API that `tools/gesture_control.py` treats as the FALLBACK. That
# module supports both — Tasks preferred, Solutions if that is what is installed — so an
# existing 3.12 environment pinned to 0.10.18 keeps working. New installs get 1.x.
#
# The Tasks API needs a model file that pip does not carry, 7.8 MB, gitignored like the
# whisper models:
#     python tools/gesture_control.py --fetch-model
#
# NOTE opencv-python is deliberately NOT listed. mediapipe pulls `opencv-contrib-python`, which
# is a superset and provides the same `cv2` module — installing both makes two distributions
# fight over the same import name. gesture_control.py only needs VideoCapture and cvtColor,
# which contrib has. If mediapipe is absent, cv2 goes too, and the module degrades to
# NO_CAMERA — which is the correct behaviour anyway.
mediapipe>=1.0                       # Tasks HandLandmarker: 21 landmarks, ~3ms/frame inference
