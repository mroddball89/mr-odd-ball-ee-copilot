# OCR — reading the PDFs that carry no text. Added 2026-08-29.
#
# `tools/vector_db.py` had always REPORTED image-only PDFs and indexed nothing from them, so
# an uploaded schematic could be filed, announced as "being indexed", and contribute zero
# chunks. Three files in data/ were in that state.
#
# **pypdfium2 rasterises the PAGE, and that is the whole reason it is here rather than a
# smarter use of pypdf.** The ESP32 DevKit schematic holds 368 embedded JPEG2000 tiles — the
# drawing was exported as fragments and a net label is routinely split across two of them, so
# OCR'ing the embedded images reads half a word at a time. Rendering the composed page reads
# it whole.
#
# Permissively licensed and a self-contained wheel, which is what rules out the alternatives:
# `pytesseract` needs the Tesseract binary installed separately, `pdf2image` needs poppler,
# and PyMuPDF is AGPL.
#
# rapidocr-onnxruntime reuses the `onnxruntime` already declared above for the wake word and
# Piper, so the OCR models sit on a runtime that is present rather than adding a second one.
# It pulls opencv-python back in as its own dependency — that is OCR's, not the gesture
# system's, and it arrives declared by the package that needs it.
#
# 200 dpi, measured rather than assumed: media/data/2026-08-29-ocr-dpi-sweep.csv shows the
# character count flat from 150 dpi up, because RapidOCR resizes to its detector's input size.
# Cached under data/.ocr_cache/, because file_manager rebuilds the store on every upload.
pypdfium2>=4.30                      # rasterises a PDF page. Apache/BSD, no system binary
rapidocr-onnxruntime>=1.3            # the OCR itself; reuses onnxruntime, pulls opencv

# The face — his window on the desktop (hud/float.py). Added 2026-08-26.
#
# PyQt6-WebEngine and NOT pywebview, and the reason is one property rather than taste.
# `--transparent` is load-bearing: the solo look is the character composited onto the desktop
# with no rectangle seam, which needs the page transparent AND the window transparent
# together. pywebview on Windows drives WebView2, whose transparency is a
# `DefaultBackgroundColor` that does not reliably reach a layered top-level window. Qt does it
# directly — `WA_TranslucentBackground` plus `page().setBackgroundColor`.
#
# It is ~150 MB, which is the single largest thing in this file, and on the Pi that trade
# could never have been made. It is the first place the new hardware actually bought something.
#
# This replaces GTK4 + WebKitGTK, which was never a pip dependency at all — it was
# `sudo apt install gir1.2-gtk-4.0 gir1.2-webkit-6.0 libwebkitgtk-6.0-4 python3-gi`, because
# PyGObject is a system package on Debian and building it from source on the Pi is a fight
# nobody needs. On Windows there is no system package and no fight; it is a wheel.
# =======================================================================================
PyQt6>=6.7                           # the window, its flags, and the escape-hatch shortcuts
PyQt6-WebEngine>=6.7                 # the WebView that renders hud/face-preview.html
