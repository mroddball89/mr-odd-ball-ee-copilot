# The assistant half — wake word, ears, voice, face. Merged from mroddball89/mr-odd-ball-ai.
#
# Lower bounds rather than pins, matching that repo: built against Python 3.12.10 on Windows
# and 3.13.5 on the Pi.
#
# TWO THINGS THAT ARE NOT IN THIS FILE and are not optional on the Pi:
#
#   sudo apt install libportaudio2 pipewire-alsa
#   pip install --no-deps "openwakeword>=0.6.0"
#
# `pipewire-alsa` is the one that is easy to miss: PortAudio speaks ALSA, and without that
# plugin ALSA has no route to the PipeWire sink the Bluetooth speaker lives on — playback
# "succeeds" into the HDMI card while the speaker sits silent.
#
# `--no-deps` because openWakeWord declares tflite-runtime as a hard dependency on Linux, and
# tflite-runtime publishes no wheels for Python 3.12+, so pip refuses to install it at all on
# the Pi. We never load tflite — config/oddball.toml sets framework = "onnx" on both boxes.
# Its real dependencies are listed at the bottom, which is what makes the flag safe.
# =======================================================================================

sounddevice>=0.5.5                   # PortAudio bindings — the microphone AND the speaker
numpy>=2.5.2
websockets>=17.0.1                   # the face link; websockets.asyncio, not the legacy API
piper-tts>=1.6.0                     # his voice. Reuses onnxruntime, so ~34MB not a 2nd runtime
faster-whisper>=1.2.1                # his ears. ctranslate2 ships a cp313 aarch64 wheel

# --- openWakeWord's real dependencies, because it is installed with --no-deps ------------
onnxruntime>=1.10,<2
tqdm>=4.0,<5.0
scipy>=1.3,<2
scikit-learn>=1,<2

# Gesture approval — a thumbs up at the camera instead of typing y (tools/gesture_control.py).
#
# NOTHING IS LISTED HERE, AND THAT IS THE ENTRY. Corrected twice; see D14 then D15.
#
# mediapipe does not go in the main venv. It goes in a SEPARATE Python 3.12 venv built by
#     bash tools/install_gesture_venv.sh
# and `tools/gesture_control.py` shells out to it for one token per approval.
#
# Why, measured on the Pi 2026-08-22:
#
#   mediapipe 1.0.1   on py3.13   installs cleanly, then SIGKILLs at XNNPACK delegate
#                                 creation. Every vision task. No OOM, 6.4 GB free.
#   mediapipe 0.10.18 on py3.12   works. Both its APIs work. 88 ms/frame.
#   mediapipe 0.10.20+            publishes no aarch64 wheel at all.
#
# So the only mediapipe that runs here needs a <=3.12 interpreter, and the main venv is 3.13.5
# because faster-whisper, ctranslate2, piper and onnxruntime were all verified there. Moving
# 1.9 GB of working audio stack to chase one leaf feature is the wrong trade; a 400 MB sidecar
# venv is the right one.
#
# Installing mediapipe into THIS venv is actively harmful, not merely useless: it drags in
# opencv-contrib-python (111 MB + deps) and makes `--backend` report a backend that will kill
# the process the moment it is used.
#
# The sidecar also needs a model file that pip does not carry, 7.8 MB, gitignored:
#     python tools/gesture_control.py --fetch-model
