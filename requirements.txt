# Mr Odd Ball — EE Copilot
# LOWER BOUNDS, NOT PINS — the same convention the assistant half already used.
#
# These were `~=` pins copied from a Windows environment where the packages were already
# installed in a mutually compatible set. On a FRESH aarch64 venv that set is unreachable:
# pinning langchain-core to ~=1.5 while langchain-community and langchain-google-genai each
# constrain it from opposite directions gave pip a ResolutionImpossible, and its error named
# langchain-core, which resolves fine on its own. An hour of the Pi bring-up went into that.
#
# A pin that only works on the machine it was captured on is not a pin, it is a snapshot. Let
# pip solve it, and pin exactly only if the two boxes ever actually disagree.

# --- LLM and routing -------------------------------------------------------------------
langchain-google-genai>=4.3          # ChatGoogleGenerativeAI, with_structured_output
pydantic>=2.13                       # RouteDecision — the router's structured output
python-dotenv>=1.2                   # GOOGLE_API_KEY out of .env, never out of source

# --- Web agent's loaders, and the text splitter -----------------------------------------
langchain-community>=0.4             # DuckDuckGoSearchRun, PyPDFDirectoryLoader
langchain-text-splitters>=1.1        # RecursiveCharacterTextSplitter

# --- Math agent ------------------------------------------------------------------------
langchain-experimental>=0.4          # PythonREPLTool
#
# The REPL runs in THIS interpreter, so "available to the agent" and "installed here" are the
# same statement. MATH_PROMPT_TEMPLATE invites it to solve filter and physics problems, and a
# library the prompt implies but the venv lacks does not degrade — it comes back as a spoken
# "ModuleNotFoundError", which is what the Pi actually said on 2026-08-19 when asked for a
# derivative. tools/verify_agents.py now checks each of these can be imported FROM the sandbox.
#
# numpy and scipy are already pulled in by the audio stack below; sympy is not, and symbolic
# work (derivatives, solving, simplification) is exactly what an EE student asks for.
sympy>=1.13

# --- Hardware agent ----------------------------------------------------------------------
#
# Reads .kicad_sch and .kicad_pcb S-expressions into Python objects. Pure Python, no compiler,
# ~93KB, and it does NOT need KiCad installed — which matters, because the Pi does not have it
# and never will. Tested against 1.4.8 on Python 3.12; tools/verify_kicad.py pins the parts of
# the API this repo actually uses, since `Schematic.symbols` (the obvious name) does not exist
# and the real one is `schematicSymbols`.
kiutils>=1.4.8

# --- Web agent -------------------------------------------------------------------------
duckduckgo-search>=8.1
ddgs>=9.15                           # the renamed package DuckDuckGoSearchRun now calls into

# =======================================================================================
# The assistant half — wake word, ears, voice, face. Merged from mroddball89/mr-odd-ball-ai.
#
# Lower bounds rather than pins, matching that repo: built against Python 3.12.10 on Windows
# and 3.13.5 on the Pi.
#
# TWO THINGS THAT ARE NOT IN THIS FILE and are not optional on the Pi:
#
#   sudo apt install libportaudio2 pipewire-alsa
#   pip install --no-deps "openwakeword>=0.6.0"
#
# `pipewire-alsa` is the one that is easy to miss: PortAudio speaks ALSA, and without that
# plugin ALSA has no route to the PipeWire sink the Bluetooth speaker lives on — playback
# "succeeds" into the HDMI card while the speaker sits silent.
#
# `--no-deps` because openWakeWord declares tflite-runtime as a hard dependency on Linux, and
# tflite-runtime publishes no wheels for Python 3.12+, so pip refuses to install it at all on
# the Pi. We never load tflite — config/oddball.toml sets framework = "onnx" on both boxes.
# Its real dependencies are listed at the bottom, which is what makes the flag safe.
# =======================================================================================

sounddevice>=0.5.5                   # PortAudio bindings — the microphone AND the speaker
numpy>=2.5.2
websockets>=17.0.1                   # the face link; websockets.asyncio, not the legacy API
piper-tts>=1.6.0                     # his voice. Reuses onnxruntime, so ~34MB not a 2nd runtime
faster-whisper>=1.2.1                # his ears. ctranslate2 ships a cp313 aarch64 wheel

# --- openWakeWord's real dependencies, because it is installed with --no-deps ------------
onnxruntime>=1.10,<2
tqdm>=4.0,<5.0
scipy>=1.3,<2
scikit-learn>=1,<2
requests>=2.0,<3
